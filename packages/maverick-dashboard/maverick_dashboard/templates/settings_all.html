Set up company sign-in

Register Lightwork with your sign-in provider, save its details under People & access below, then check the connection. A connection check reads the provider's published details; it cannot prove that a person can sign in. A local-only installation cannot switch over on this check alone: it needs a verified alternate sign-in or recovery path first. After a verified sign-in and an explicit administrator grant, use the reviewed activation and restricted recovery controls below.

Company account (OpenID Connect)

Save the copied address in Return address after sign-in, and register the same address with your provider. Then enter the provider address and application details. Use the provider's application name for both Lightwork's name and accepted sign-in audience, unless your provider specifies a different audience.

Continue to your sign-in provider

This opens your provider in another tab and verifies a real sign-in against the saved details. It keeps your current access and does not turn company sign-in on or grant anyone access. Save the provider details first; unsaved edits are not tested.

    Single sign-on (SAML)

    Use the guided single sign-on setup to upload your provider's document, keep it inactive, verify a real sign-in and review activation. Current local access stays available while you prepare and test the connection.

    Open Lightwork at its public secure web address before using the values below. An unsecured local address cannot be registered as the single sign-on return address.

    Save the copied return address in Single sign-on return address and the copied identity in Lightwork's name for single sign-on. Register those same values with your provider. Then enter your provider's metadata address; using that address avoids moving a file onto the server.

    Company proxy

    Review proxy sign-in only if the proxy is the sole route to Lightwork. Enter the header it sends and the exact proxy addresses Lightwork should trust. This page cannot verify a proxy sign-in from outside that route.

    Before requiring sign-in for everyone, add the intended administrators under Users and verify a real sign-in. Lightwork refuses settings changes that would remove the current administrator's only access.

    Configuration profiles, presets and history

    Profiles contain selected supported preferences only. Credentials, personal names, policy documents and deployment identities are excluded. Imported values use the same review, conflict checks and permissions as ordinary settings.

    Leave selections empty to export every supported preference. Use each row's Export preference checkbox to select fields.

      What can't be changed here

      A setting marked “Set by your server's deployment settings” is fixed by whoever runs your server, so it can only be changed there. So are the main encryption key and the folder Lightwork keeps its files in: they protect or start Lightwork itself.

      Sign-in, administrator and key settings are checked before they are saved. A change that would lock you out, or leave saved records unreadable, is refused until its test passes. You are asked to confirm before you are signed out.

      AI service keys, models, the spending cap per task, features, abilities, connections and plugins have their own sections on the Settings page and their own pages. The sign-in details of the six chat apps are on the Channels page. The security suite's on and off switches are on the Security page.
