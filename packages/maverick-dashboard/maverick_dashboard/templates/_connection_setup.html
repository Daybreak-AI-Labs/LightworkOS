Sign-in-based connections are off. Key-based connections still work. Turning this on lets people sign in to Google, Atlassian or Microsoft accounts here and lets Lightwork renew that access when work needs it.

Turn off account connections

Accounts connected here (Google Drive, Google Cloud Storage, Jira Cloud and Microsoft email) stop working straight away. Workflows and email that use them can't read or change anything through them, and nobody can connect a new account. Their saved sign-in stays stored and encrypted, so turning this back on makes them work again. To remove an account for good, use its own remove button instead.

For the person who installed Lightwork: set up the account provider

Before anyone can connect an account, the app Lightwork uses must be set up once. Google Cloud Console · Atlassian developer console · Microsoft Entra app registrations. Create an app there, add the return address below, then paste the app's ID and secret here. The secret is encrypted and never shown again.

For Microsoft email, register an app that allows accounts in any organizational directory. Add the exact return addresses below as Web addresses, and create an app secret. Add delegated Office 365 Exchange Online permissions for reading the signed-in mailbox and sending its replies. Microsoft calls these IMAP.AccessAsUser.All and SMTP.Send. Your administrator may need to approve the app and enable incoming mail and authenticated outgoing mail for the mailbox. Lightwork cannot change your organization's Microsoft rules.
