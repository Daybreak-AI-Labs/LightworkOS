# Budget guidance and accounting help

`/budget` and the preflight details on Chat/task retry use the same task-limit resolver as launch. Requested values can only lower the configured ceiling. Preview creates no Budget, paid provider request, reservation or cap increase. Task limits apply to the next attempt; historical provider receipts are shown separately. Native clients use the same local helper or the authenticated dashboard preview for their actual launch runtime.

Personal acknowledged usage, workspace allowance and provider authority have different populations and settlement timing. They are never added together. The minimum applicable headroom is advisory; missing policy, unidentified enforced principal, corrupt accounting or unknown reservation amount makes complete headroom unavailable. Admission remains authoritative at dispatch. Daily reset is midnight UTC and the UI also formats the user's local time. Provider accounting retains its own original period. Legacy or uncapped provider activity without a linked receipt is not silently treated as invoice evidence.

`budget.guidance`, `budget.warnings` and `budget.warning_thresholds` are available in the installer and All settings. Threshold observation follows acknowledged usage and interactive previews. A durable receipt deduplicates each principal/dimension/period/threshold; personal delivery uses the existing authorized notification source projection and its preferences. Notice failure cannot invalidate an acknowledged charge. Upcoming schedule forecasts include only the current account's active definitions due before reset. Schedule ceilings are not assumed actual future charges; pause/resume remains an explicit schedule decision.

Employees can file a minimized accounting help case directly from a blocked provider. The case discloses the provider, period and their exact receipt references, never task text or a global ledger. Installation administrators explicitly claim cases, request final receipt evidence and use the existing governed Provider spending reconciliation. Case progress is CAS-versioned and audited. Verification rereads the original period and requires readable accounting without unresolved/pending reservations; changing the date or increasing a ceiling cannot masquerade as a refund or reconciliation. The UI exposes pending audit delivery. No action retries provider work.

Browser, concurrency, revocation, shared-store and provider-invoice behavior is not qualified.
