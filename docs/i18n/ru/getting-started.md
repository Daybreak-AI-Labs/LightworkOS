# Начало работы

Разделы первого запуска и мониторинга обновлены по этой редакции; другие разделы могут отставать от английского оригинала. [English](../../getting-started.md).

## Установка

Lightwork устанавливается из исходного кода; нужны Python 3.11–3.12 и Git. Следуйте [инструкции по установке из исходного кода](../../source-install.md): в ней приведены команды для macOS, Linux и Windows. Готовые исполняемые файлы, пакеты PyPI и образы контейнеров пока не публикуются. Сейчас ни одна версия не опубликована; устанавливайте из `main`.

Затем запустите `lightwork dashboard` и откройте <http://127.0.0.1:8765>, чтобы завершить настройку владельца и поставщика моделей.

## Первый запуск

В панели откройте **Start → Set up named sign-in**, прежде чем приглашать команду. Локальный владелец задаёт адрес электронной почты как идентификатор и парольную фразу; это закрывает анонимный доступ администратора. Адрес служит локальной меткой личности: почтовый ящик не проверяется. Храните ссылки-приглашения в тайне. Для повторного входа на этом компьютере используйте `/auth/local-login`. Права на рабочее пространство и отделы назначаются в **Users**.

Настройка первого владельца принимает только прямые локальные запросы на этом компьютере до назначения ролей или настройки управляемого входа. `[dashboard] local_owner_setup` по умолчанию равен `true`; `MAVERICK_LOCAL_OWNER_SETUP=0` отключает регистрацию. Действующие политики входа и приглашений сохраняют силу.

Мастер настройки и проверки доступны также в терминале:

```bash
lightwork init
lightwork preflight
lightwork doctor
```

Мастер записывает `~/.maverick/config.toml` и `~/.maverick/.env`. При новой персональной настройке предлагаются лимиты $2 и 30 минут на задачу; можно выбрать другие лимиты или отказаться от них. Изменить выбор можно в **Settings → General → Spending per task**. Без лимита задачи расходы всё равно учитываются и оплачиваются поставщику модели; лимиты организации продолжают действовать. См. [лимиты задач](../../task-limits.md).

Если работающий демон Docker не найден, изменение файлов и выполнение программ отключены: запасной backend `local` выполнял бы команды прямо на этом компьютере без изоляции. Начните с такой задачи:

```bash
lightwork start "Draft a one-page plan to reduce our customer support response time without adding headcount. State your assumptions and the facts you need from me."
```

## Наблюдайте, как рой декомпозирует цель

Запустите `lightwork monitor` во втором терминале. Пример плана для первой задачи:

```
Goal #1 active  2m elapsed
Draft a one-page support response plan

Plan tree
  ├─        done  #2 Identify likely response-time bottlenecks
  ├─      active  #3 Draft actions that do not require hiring
  └─     pending  #4 Check assumptions and questions for the owner

Latest episode #7 (running)  $0.0431  in=18,204 out=2,910 tools=11

Recent activity
  4s ago [researcher] decision: separate volume from process delays
  3s ago [writer] draft: owner-facing plan with assumptions
  1s ago [verifier] review: mark unsupported savings estimates

Cumulative spend on this DB: $0.21
```

Чтобы позже изменять файлы или запускать программы, запустите Docker или Podman, выберите контейнер в **Permissions → Where work runs** и подтвердите **Allow file work**. Lightwork проверит контейнер и покажет другие блокирующие политики; `lightwork doctor` показывает то же ограничение.

Когда всё готово:

```bash
maverick status      # what's currently active or blocked
maverick skills      # what the swarm distilled from this run
maverick facts       # what it learned about you
```

## Пауза и возобновление

Если рою нужно что-то, на что можете ответить только вы, он приостанавливается и ставит вопрос в очередь:

```bash
maverick status
# shows: open questions: #3 (goal 1): Which dates are you traveling?

maverick answer 3 "May 15-29"
maverick resume
```

Цели переживают перезапуски. Вы можете закрыть ноутбук и вернуться завтра.

## Отмена правок файлов, сделанных запуском

С включённым журналом рабочего пространства (`[workspace] journal = true`,
либо ответив «да» на шаге *Workspace journal* мастера установки) каждый файл,
который агенты перезаписывают или создают через файловые инструменты,
фиксируется до изменения:

```bash
maverick journal list --goal 12     # что было затронуто
maverick journal diff --goal 12     # состояние до запуска и диск сейчас
maverick journal revert --goal 12   # восстановить все файлы, начиная с новейших
```

Откат записывает подписанную строку аудита `workspace_revert` и архивирует
журнал. Изменения через shell (`rm`, `mv`, перенаправления) в журнал не
попадают — эти команды фиксирует аудиторский след.

## Создание собственного специалиста из наблюдаемой задачи

Вам не обязательно описывать работу словами — вы можете её показать. Запишите
упорядоченный журнал того, как кто-то выполняет работу (предпринятые действия и
любые пояснения, почему именно так), в формате JSONL или простого текста с
префиксами, а затем передайте файл Lightwork:

```
ACTION[gmail]: send the morning digest -> ops@acme.com
NOTE: only the top 5 stories, with one-line summaries
SEE: digest looks right, ops confirmed receipt
```

```bash
maverick learn-demo demo.txt
```

Это разбирает демонстрацию, выводит черновик специалиста, показывает вам
полученный рабочий процесс и ждёт вашего одобрения, прежде чем сохранить. Секреты
скрываются ещё на входе, а черновик наследует тот же зажим возможностей и
проверку персоны, что и описанный пак, — ничего не активируется без вашего
согласия. Полезные флаги:

```bash
maverick learn-demo demo.txt --name "Morning Digest" --no-llm --yes
```

`--no-llm` детерминированно повторяет наблюдаемые шаги (инструменты = то, чем
пользовался человек); уберите его, чтобы модель предложила вариант на основе
транскрипта.

Тот же процесс фабрики агентов запускается, когда вы собираете пак в режиме
диалога:

```bash
maverick onboard
```

После одобрения `onboard` теперь обеспечивает пак всем необходимым — он
устанавливает навыки из каталога, которые нужны его рабочему процессу, и
синтезирует любые объявленные инструменты, которых нет среди встроенных, так что
только что одобренный специалист готов к работе с первого запуска. (Этот шаг
учитывает конфигурацию `[self_learning]` / `provision_packs` и никогда не
расширяет зажатую оболочку прав пака.)

## Голосовой ввод (встроенный, офлайн)

Кнопка микрофона в панели и инструмент `transcribe_audio` работают без ключа
провайдера: локальный движок Whisper поставляется вместе с пакетом панели, а
при открытии приложения файлы модели по умолчанию не скачиваются. В разделе
голосовой диктовки на вкладке **Settings → Models** глобальный
администратор может проверить источник и размер настроенной модели (около
148 МБ для модели по умолчанию), затем проверить или скачать её. Прогресс
сохраняется после перезагрузки страницы; отмена удаляет незавершённую загрузку,
а после сбоя её можно повторить на том же экране. Существующие файлы не
помечаются как проверенные, пока их точный размер и контрольная сумма не
совпадут. Проверка модели не подтверждает, что речевой движок загружен или
что микрофон работает.

Установщик явно спрашивает, разрешать ли загрузки при запуске. Сохранённое
`[voice] auto_fetch_model = true` или `MAVERICK_VOICE_AUTO_FETCH=1` по-прежнему
включает их. Сетевая политика всегда применяется, в том числе к перенаправлениям.
Настроенные администратором пути к пользовательским моделям и выбранный
облачный бэкенд распознавания речи сохраняются: этот экран не заменяет их
без явного действия. Также доступен CLI:

```bash
maverick voice setup    # скачивает модель с проверкой контрольной суммы (~148 МБ)
maverick voice status   # показывает, какие backend'ы распознавания речи доступны
maverick voice transcribe clip.wav   # быстрая проверка конвейера
```

Предпочитаете системный движок? Бинарник `whisper.cpp` в PATH
(`brew install whisper-cpp`) или faster-whisper встраиваются в ту же
цепочку. Задайте `[voice] stt_backend = "local"`, чтобы аудио не покидало
машину даже при настроенных ключах OpenAI/Groq.

## Смена моделей и провайдеров

После установки изменяйте выбор в разделах **Settings → Provider keys**
или **Settings → Models**. На странице отмечены значения, которыми управляет
развёртывание. Чтобы новое значение вступило в силу, администратор установки
должен изменить его источник. Базовые параметры описаны в
[`configuration.md`](../../configuration.md).

## Где хранятся данные

| Файл | Что это |
|---|---|
| `~/.maverick/config.toml` | Ваша конфигурация (развёртывание, модели, безопасность, бюджет) |
| `~/.maverick/.env` | API-ключи (chmod 600) |
| `~/.maverick/world.db` | Персистентная модель мира: цели, факты, эпизоды |
| `~/.maverick/skills/` | Файлы SKILL.md, автоматически извлечённые из успешных запусков |
| `~/maverick-workspace/` | Рабочий каталог песочницы по умолчанию |
| `~/.maverick/learned-skills/` | Навыки, извлечённые циклами обучения |
| `~/.maverick/dreams/` | Сводные инсайты, очередь репетиций, снимки обучения |

Lightwork хранит перечисленные выше файлы в вашем развёртывании. Если включить
облачных AI-провайдеров или подключённые сервисы, передаваемые через них рабочие
данные могут покидать это развёртывание. Перед использованием проверьте каждого
провайдера, коннектор и политику исходящих соединений.

Когда у вас за плечами будет несколько запусков, поверхность обучения сводится к
четырём командам: `maverick dream` (консолидировать опыт), `maverick hindsight`
(помогло обучение или, наоборот, ухудшило результат?), `maverick proof`
(результаты работы, сэкономленные затраты, ROI) и `maverick domains-lint`
(аудит каталога специалистов), а также `maverick domains-audit`
(состояние управления: до чего может дотянуться каждый агент, что запрещает и в
чём отказывает) и `maverick domains-eval --check` (эталонные поведенческие
случаи).
