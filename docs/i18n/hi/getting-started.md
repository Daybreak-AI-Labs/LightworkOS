# शुरुआत करें

इस संशोधन के अनुसार पहले रन और मॉनिटर वाले भाग अद्यतन किए गए हैं; दूसरे भाग अंग्रेज़ी मूल से पुराने हो सकते हैं। [English](../../getting-started.md).

## इंस्टॉल

Lightwork को सोर्स कोड से इंस्टॉल किया जाता है; इसके लिए Python 3.11–3.12 और Git चाहिए। macOS, Linux और Windows के कमांड [सोर्स से इंस्टॉल मार्गदर्शिका](../../source-install.md) में दिए गए हैं। पहले से बनी बाइनरी फ़ाइलें, PyPI पैकेज और कंटेनर इमेज अभी प्रकाशित नहीं हैं। अभी कोई रिलीज़ प्रकाशित नहीं है; `main` से इंस्टॉल करें।

इसके बाद `lightwork dashboard` चलाएँ और <http://127.0.0.1:8765> खोलकर मालिक और मॉडल प्रदाता का सेटअप पूरा करें।

## पहली बार चलाना

टीम को आमंत्रित करने से पहले डैशबोर्ड में **Start → Set up named sign-in** खोलें। स्थानीय मालिक ईमेल पहचान और पासफ़्रेज़ चुनता है; इससे अनाम व्यवस्थापक पहुँच बंद हो जाती है। ईमेल केवल स्थानीय पहचान है, मेलबॉक्स सत्यापित नहीं होता। आमंत्रण लिंक निजी रखें। इस कंप्यूटर पर दोबारा साइन इन करने के लिए `/auth/local-login` इस्तेमाल करें। कार्यक्षेत्र और विभाग के अधिकार **Users** में दें।

पहले मालिक का सेटअप केवल इसी कंप्यूटर से सीधे लूपबैक अनुरोध स्वीकार करता है, और वह भी भूमिकाएँ या प्रबंधित साइन-इन कॉन्फ़िगर होने से पहले। `[dashboard] local_owner_setup` का डिफ़ॉल्ट `true` है; `MAVERICK_LOCAL_OWNER_SETUP=0` नामांकन बंद करता है। मौजूदा साइन-इन और आमंत्रण नीतियाँ लागू रहती हैं।

विज़ार्ड और उसकी जाँचें कमांड लाइन से भी चलती हैं:

```bash
lightwork init
lightwork preflight
lightwork doctor
```

विज़ार्ड `~/.maverick/config.toml` और `~/.maverick/.env` लिखता है। नया निजी सेटअप प्रति कार्य $2 और 30 मिनट की सीमा सुझाता है; आप दूसरी सीमा चुन सकते हैं या बिना सीमा के काम कर सकते हैं। इसे बाद में **Settings → General → Spending per task** में बदलें। कार्य की सीमा न होने पर भी खर्च दर्ज होता है, मॉडल प्रदाता शुल्क लेता है और संगठन की खर्च सीमा लागू रहती है। [कार्य सीमाएँ](../../task-limits.md) देखें।

अगर चल रहा Docker daemon नहीं मिला, तो फ़ाइल बदलाव और प्रोग्राम चलाना बंद कर दिया जाता है: वैकल्पिक `local` बैकएंड इस कंप्यूटर पर बिना अलगाव के सीधे कमांड चलाएगा। इस कार्य से शुरुआत करें:

```bash
lightwork start "Draft a one-page plan to reduce our customer support response time without adding headcount. State your assumptions and the facts you need from me."
```

## स्वार्म को लक्ष्य विभाजित करते हुए देखें

दूसरे टर्मिनल में `lightwork monitor` चलाएँ। पहले कार्य की योजना का एक उदाहरण:

```
Goal #1 active  2m elapsed
Draft a one-page support response plan

Plan tree
  ├─        done  #2 Identify likely response-time bottlenecks
  ├─      active  #3 Draft actions that do not require hiring
  └─     pending  #4 Check assumptions and questions for the owner

Latest episode #7 (running)  $0.0431  in=18,204 out=2,910 tools=11

Recent activity
  4s ago [researcher] decision: separate volume from process delays
  3s ago [writer] draft: owner-facing plan with assumptions
  1s ago [verifier] review: mark unsupported savings estimates

Cumulative spend on this DB: $0.21
```

बाद में फ़ाइल बदलने या प्रोग्राम चलाने के लिए Docker या Podman शुरू करें, **Permissions → Where work runs** में कंटेनर चुनें और **Allow file work** की पुष्टि करें। Lightwork कंटेनर जाँचता है और अन्य रोकने वाली नीतियाँ दिखाता है; `lightwork doctor` भी यही सीमा दिखाता है।

काम पूरा होने पर:

```bash
maverick status      # what's currently active or blocked
maverick skills      # what the swarm distilled from this run
maverick facts       # what it learned about you
```

## रोकना / फिर से शुरू करना

अगर स्वार्म को कोई ऐसी जानकारी चाहिए जो केवल आप दे सकते हैं, तो वह रुक जाता है और सवाल को कतार में डाल देता है:

```bash
maverick status
# shows: open questions: #3 (goal 1): Which dates are you traveling?

maverick answer 3 "May 15-29"
maverick resume
```

लक्ष्य रीस्टार्ट के बाद भी बने रहते हैं। आप लैपटॉप बंद करके कल वापस आ सकते हैं।

## किसी रन के फ़ाइल संपादनों को पूर्ववत करना

वर्कस्पेस जर्नल चालू होने पर (`[workspace] journal = true`, या विज़ार्ड के
*Workspace journal* चरण में हाँ चुनने पर), एजेंट फ़ाइल टूल्स से जो भी फ़ाइल
अधिलेखित या निर्मित करते हैं, वह परिवर्तन से पहले दर्ज कर ली जाती है:

```bash
maverick journal list --goal 12     # क्या-क्या बदला गया
maverick journal diff --goal 12     # रन से पहले की स्थिति बनाम अभी की डिस्क
maverick journal revert --goal 12   # हर फ़ाइल को पुनर्स्थापित करें, नवीनतम पहले
```

रिवर्ट एक हस्ताक्षरित `workspace_revert` ऑडिट पंक्ति लिखता है और जर्नल को
संग्रहीत कर देता है। शेल से किए गए परिवर्तन (`rm`, `mv`, रीडायरेक्ट) जर्नल में
दर्ज नहीं होते — उन कमांड्स को ऑडिट ट्रेल दर्ज करता है।

## किसी देखे गए कार्य से अपना खुद का विशेषज्ञ बनाना

आपको किसी काम को शब्दों में बताने की ज़रूरत नहीं है — आप उसे दिखा सकते हैं। किसी व्यक्ति
को वह काम करते हुए का एक क्रमबद्ध रिकॉर्ड (उसने जो कार्रवाइयाँ कीं और क्यों कीं, उसका कोई
भी विवरण) JSONL या साधारण प्रीफ़िक्स्ड टेक्स्ट के रूप में कैप्चर करें, फिर वह फ़ाइल Lightwork
को सौंप दें:

```
ACTION[gmail]: send the morning digest -> ops@acme.com
NOTE: only the top 5 stories, with one-line summaries
SEE: digest looks right, ops confirmed receipt
```

```bash
maverick learn-demo demo.txt
```

यह डेमॉन्स्ट्रेशन को पार्स करता है, एक ड्राफ़्ट विशेषज्ञ तैयार करता है, आपको व्युत्पन्न
वर्कफ़्लो दिखाता है, और सहेजने से पहले आपकी मंज़ूरी का इंतज़ार करता है। सीक्रेट्स दरवाज़े पर ही
हटा दिए जाते हैं, और ड्राफ़्ट को वही कैपेबिलिटी क्लैंप और पर्सोना स्कैन मिलता है जो किसी
वर्णित पैक को मिलता है — आपकी हाँ के बिना कुछ भी सक्रिय नहीं होता। उपयोगी फ़्लैग्स:

```bash
maverick learn-demo demo.txt --name "Morning Digest" --no-llm --yes
```

`--no-llm` देखे गए चरणों को नियतात्मक रूप से प्रतिबिंबित करता है (टूल्स = जो व्यक्ति ने
इस्तेमाल किए); इसे हटा दें ताकि मॉडल ट्रांसक्रिप्ट से सुझाव दे सके।

जब आप किसी पैक को बातचीत के ज़रिए बनाते हैं, तब भी वही एजेंट-फ़ैक्टरी प्रवाह चलता है:

```bash
maverick onboard
```

मंज़ूरी मिलने पर, `onboard` अब पैक को प्रोविज़न करता है — यह उसके वर्कफ़्लो के लिए ज़रूरी
कैटलॉग स्किल्स इंस्टॉल करता है और किसी भी ऐसे घोषित टूल को संश्लेषित करता है जो पहले से
मौजूद नहीं है, ताकि एक नया-मंज़ूर किया गया विशेषज्ञ पहले ही रन से अपना काम करने के लिए
तैयार रहे। (यह चरण `[self_learning]` / `provision_packs` कॉन्फ़िगरेशन का सम्मान करता है और
पैक के क्लैंप्ड दायरे को कभी नहीं बढ़ाता।)

## वॉइस इनपुट (बिल्ट-इन, ऑफ़लाइन)

डैशबोर्ड का माइक बटन और `transcribe_audio` टूल बिना किसी प्रोवाइडर कुंजी के
काम करते हैं: लोकल Whisper इंजन डैशबोर्ड पैकेज के साथ आता है, लेकिन ऐप खोलने
पर डिफ़ॉल्ट रूप से मॉडल फ़ाइलें डाउनलोड नहीं होतीं।
**Settings → Models** के वॉइस डिक्टेशन सेक्शन में ग्लोबल एडमिन कॉन्फ़िगर किए गए मॉडल का स्रोत और आकार (डिफ़ॉल्ट मॉडल
के लिए लगभग 148 MB) देख सकता है, फिर उसे जाँच या डाउनलोड कर सकता है। पेज
रीलोड करने पर प्रगति बनी रहती है; रद्द करने पर अधूरा डाउनलोड हट जाता है और
विफल होने पर उसी स्क्रीन से दोबारा कोशिश की जा सकती है। मौजूदा फ़ाइलों को
सटीक आकार और चेकसम की जाँच पास करने के बाद ही सत्यापित दिखाया जाता है। मॉडल
का सत्यापन यह साबित नहीं करता कि स्पीच इंजन लोड है या माइक्रोफ़ोन काम कर रहा है।

इंस्टॉलर स्टार्टअप पर डाउनलोड की अनुमति के बारे में स्पष्ट रूप से पूछता है। पहले
से सहेजी गई `[voice] auto_fetch_model = true` सेटिंग या
`MAVERICK_VOICE_AUTO_FETCH=1` अब भी स्टार्टअप डाउनलोड चालू करती है। नेटवर्क
नीति रीडायरेक्ट सहित हमेशा लागू होती है। एडमिन द्वारा प्रबंधित कस्टम मॉडल पथ
और चुने गए क्लाउड स्पीच बैकएंड की सेटिंग बनी रहती है; यह स्क्रीन उन्हें चुपचाप
नहीं बदलती। वैकल्पिक CLI भी उपलब्ध है:

```bash
maverick voice setup    # checksum-सत्यापित मॉडल डाउनलोड करें (~148 MB)
maverick voice status   # देखें कि कौन से speech-to-text backend उपलब्ध हैं
maverick voice transcribe clip.wav   # पाइपलाइन का त्वरित परीक्षण
```

सिस्टम इंजन पसंद है? PATH में मौजूद `whisper.cpp` बाइनरी
(`brew install whisper-cpp`) या faster-whisper उसी चेन में जुड़ जाते हैं।
`[voice] stt_backend = "local"` सेट करने पर OpenAI/Groq keys कॉन्फ़िगर होने
पर भी ऑडियो मशीन से बाहर नहीं जाता।

## मॉडल या प्रोवाइडर बदलना

इंस्टॉलेशन के बाद विकल्प बदलने के लिए **Settings → Provider keys** या
**Settings → Models** खोलें। डिप्लॉयमेंट द्वारा नियंत्रित मान पेज पर चिह्नित होते
हैं। नया मान लागू करने के लिए इंस्टॉलेशन एडमिन को उस मान का स्रोत बदलना होगा।
मूल सेटिंग्स के लिए [`configuration.md`](../../configuration.md) देखें।

## डेटा कहाँ रहता है

| फ़ाइल | विवरण |
|---|---|
| `~/.maverick/config.toml` | आपका कॉन्फ़िगरेशन (डिप्लॉयमेंट, मॉडल, सेफ़्टी, बजट) |
| `~/.maverick/.env` | API कुंजियाँ (chmod 600) |
| `~/.maverick/world.db` | स्थायी वर्ल्ड मॉडल: लक्ष्य, तथ्य, एपिसोड |
| `~/.maverick/skills/` | सफल रन से अपने आप डिस्टिल की गई SKILL.md फ़ाइलें |
| `~/maverick-workspace/` | सैंडबॉक्स की डिफ़ॉल्ट वर्किंग डायरेक्टरी |
| `~/.maverick/learned-skills/` | लर्निंग लूप्स द्वारा डिस्टिल की गई स्किल्स |
| `~/.maverick/dreams/` | समेकित अंतर्दृष्टियाँ, रिहर्सल कतार, लर्निंग स्नैपशॉट्स |

Lightwork ऊपर सूचीबद्ध फ़ाइलें आपके डिप्लॉयमेंट में रखता है। यदि आप क्लाउड AI
प्रोवाइडर या कनेक्टेड सेवाएँ चालू करते हैं, तो उनके ज़रिए भेजा गया काम उस
डिप्लॉयमेंट से बाहर जा सकता है। उपयोग से पहले हर प्रोवाइडर, कनेक्टर और आउटबाउंड
नीति की समीक्षा करें।

जब आपके पीछे कुछ रन हो जाएँ, तो लर्निंग सतह चार कमांड हैं:
`maverick dream` (अनुभव को समेकित करता है), `maverick hindsight` (क्या लर्निंग ने मदद की
या प्रतिगमन किया?), `maverick proof` (डिलिवरेबल्स, बचाई गई लागत, ROI), और
`maverick domains-lint` (विशेषज्ञ कैटलॉग का ऑडिट), साथ ही
`maverick domains-audit` (गवर्नेंस स्थिति: हर एजेंट किस तक पहुँच सकता है, किसे अस्वीकार करता
है, और किसे मना करता है) और `maverick domains-eval --check` (व्यवहारगत गोल्डन केस)।
