# Personal data and verified channel links

Enable `features.personal_data_controls` in Settings or the installer to make
**Account > My Data** available to named current workspace members. This does
not enable the independent `dreaming.user_notes` administrator ceiling. Existing
per-channel recall restrictions continue to apply if the new feature is turned
off. No personal setting grants tools, roles or companion sources.

Linking requires a ten-minute random challenge issued to the signed-in dashboard,
a normal `LIGHTWORK LINK ...` message through an authenticated supported adapter,
and a separate dashboard confirmation of the observed sender. The command is
consumed before task or conversation creation. The encrypted record contains a
native `sender_id` distinct from the conversation `user_id`, and the verified
delivery receipt's `account_sha256`. Audit events contain operation metadata,
never command tokens or note text. A link is not a task-mutation grant.

New supported-channel conversations and goal owners include the authenticated
adapter account and sender. Runtime execution principals remain unchanged so
existing capability assignments are not widened. Legacy accountless history
remains separate and requires an independently governed subject-data export;
the product does not infer ownership from a repeated sender ID. Queue envelopes
retain the account-bound world identity. No provider credentials are changed.

Personal notes show consolidation source identifiers, source date and revision,
or an explicit legacy-source-unavailable label. The source route rechecks exact
owned conversation scope. Edits, deletion suppression and topic suppression are
encrypted, revision-bound and consulted by consolidation and recall. Personal
recall-off stops collection and recall; it does not erase business history.

Sharing defaults to channel-only. The employee must choose one currently verified
source as authoritative for conflicts; its notes and account response style then
apply to linked channels. Unlinking, feature disablement or lost membership stops
future linked recall. This has no authority effect on tools, tasks or companions.

My Data separately inventories personal notes, authorized conversations and tasks,
private editor recovery copies and companion history. Selected-scope exports use
the existing strict data-rights exporter. Shared knowledge derivatives, copied
packets, external systems and prior models are explicitly separate. A task owner
can narrow future automatic local reuse and learning using the existing durable
learning exclusion policy; it is not model unlearning. Consolidated per-store
erasure uses the reviewed request process below; authorized knowledge-lineage
requests remain in Knowledge Access.

Installed-browser and live provider behavior are not qualified.

## Recalled content isolation

Task content ownership is checked before lexical/embedding ranking. Reflections and dream insights retain exact owner and source task IDs; a missing owner on an older record is not a shared-content grant. Generated skills retain server-stamped task lineage, which is rechecked before load, ranking and prompt rendering. Deleted or excluded sources stop future automatic recall. Private namespace facts never enter the workspace standing prompt. The model-managed memory tool uses a separate tenant/owner root; legacy shared files are retained outside automatic recall. Private failures cannot become shared rehearsals or organization harness lessons. These controls do not erase previously trained models or external copies.

## Reviewed personal deletion

My Data previews a verified conversation scope plus explicitly selected account-wide stores. The employee submits that snapshot; a different current workspace administrator confirms external preservation obligations and dispatches it. This process grants no private-content read authority. Recorded workspace holds block deletion even if the optional rights feature is disabled. Source changes require a new request.

Each store has durable requested, held, dispatching, purged, partial or unconfirmed state. An interrupted dispatch is never automatically repeated. Conversation deletion requires a signed durable exact-ID receipt and reports database residual counts plus attachment-file outcomes. Independently owned tasks outside that conversation closure are not silently included. Draft erasure publishes an encrypted revision barrier before file removal so old tabs cannot resurrect its content. Notes are removed with personal recall disabled; hashed suppression restrictions remain separate. Administrator companion policy remains intact.

Shared packets, knowledge derivatives, already trained models, external copies, source-linked learning files, legacy memory with unknown ownership and content-minimized governance evidence remain explicit exceptions. Knowledge Access provides source-purpose and rights-request follow-up. Diagnostic downloads are separate owned records; expiry of a link never means deletion. Notification delivery history uses the mobile worker's ownership-verified adapter. Point-in-time deletion does not disable accounts or every future collection path.

Activation preparation records and personal project defaults are separately selectable stores. Erasure keeps content-free revision tombstones, so an old save or deterministic activation operation cannot recreate removed private inputs. Activation records with an admitting, active, missing or ambiguously owned task are blocked; source tasks, admission receipts and created workflows stay separate. Project defaults erasure never changes shared project structure. Both adapters require exact ownership, reviewed revisions and acknowledged audit receipts; an unacknowledged receipt is reported as unconfirmed.

Shared harness lessons and automatically harvested evaluation cases require durable current unowned-source lineage. Legacy unknown-source rows stay in raw storage for retention and governed cleanup but cannot appear in shared prompts, search, lesson pages, trial outcomes or provider evaluation. A review of visible pending cases preserves hidden historical rows. Fresh checks apply before proposing, evaluating, judging and using memoized evaluation results; machine-source metadata survives staging, review, and immutable evaluation manifests. Hand-authored operator corpus entries remain explicitly supplied business exercises. The shared learning activity log projects operation metadata and never old free-text lessons.


Owned model-test receipts and queued conversation messages/files are separate inventory, export and reviewed-erasure choices. Active or unknown tests and consuming/dispatching queue items require reconciliation first. Erasure retains content-free operation IDs and generation barriers, so stale execute or editor requests cannot recreate the erased content. A separate reviewer is attributed explicitly; pending audit delivery is unconfirmed, never a successful purge claim.

Generated-tool reviews carry opaque name/digest keys, not private generated names. The current exact owner and source digest are checked again under the deletion lock before consent revocation and source removal. The owner can inspect available learning lineage, while unknown, excluded, unavailable or unconsented files remain explicitly outside this selection. Empty current inventories do not certify zero retained derived files or model unlearning.

My Data account-download links contain no copied bundle, expire after ten minutes, and require the same currently authorized named account/workspace at download. Conversation scope links also recheck verified ownership; actual publication requires acknowledged audit. Fourteen shared Copilot adapters use the native identity, memory, provenance, exclusion, export and deletion services with the same current context/revisions and separate review rules. All personal controls remain reachable directly at `/my-data`.

Installed cross-user browser scenarios are not qualified.
